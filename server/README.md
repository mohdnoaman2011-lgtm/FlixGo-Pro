خادم الاستخراج لـ FlixGo
خادم صغير (Node 18+) يطبّق واجهة docs/BACKEND.md. استخراج صفحات المنصات يحتاج yt-dlp؛ صورة Docker تثبّته تلقائياً.
ماذا يستخرج
روابط الملفات المباشرة (.mp4 و.mp3 وغيرها).
صفحات تعرض ملف الفيديو علناً عبر معايير الويب المفتوحة: og:video وJSON-LD (VideoObject.contentUrl) ووسوم <video> و<source> و<audio>.
ما لا يستخرجه
صفحات المنصات التي لا تكشف رابط الملف في صفحتها (أغلب منصات التواصل). لا يوجد فيه كود خاص بأي منصة.
البث المجزّأ (.m3u8 و.mpd).
المحتوى المحمي بتسجيل الدخول أو بحقوق النشر. المسؤولية على من يشغّل الخادم.
تشغيل محلي
يتطلب Node.js 18+؛ لدعم المنصات ثبّت yt-dlp بشكل منفصل واجعله متاحاً في PATH. بدون ذلك يستمر دعم الروابط المباشرة ووسوم HTML العامة.
cd server
node server.js        # المنفذ 8080
curl "http://localhost:8080/resolve?url=https://example.com/video.mp4"
الرفع على Render (مجاني)
ارفع مجلد server إلى مستودع GitHub (يمكن أن يكون في جذره أو داخل المستودع الحالي).
في render.com: New ← Web Service ← اختر المستودع.
Runtime: Docker (يستخدم Dockerfile)، وإن كان المجلد داخل مستودع المشروع فاجعل Root Directory = server.
بعد النشر تحصل على عنوان مثل https://flixgo-resolver.onrender.com. اختبره بفتح /health.
في التطبيق: الإعدادات ← «خادم الاستخراج» ← ألصق العنوان (بدون /resolve).
الخطة المجانية تنام بعد فترة خمول، فأول طلب قد يستغرق نحو 30 ثانية.
الأمان
يمنع الوصول إلى العناوين الداخلية (حماية SSRF) ويحدّ الطلبات بـ 30 في الدقيقة لكل عنوان.
ALLOWED_HOSTS=example.com,cdn.example.com يقصر الخادم على نطاقاتك أنت (مستحسن بشدة إن كان المحتوى محتواك).
API_KEY يطلب مفتاحاً في الترويسة x-api-key. التطبيق الحالي لا يرسل مفتاحاً، فاستخدم ALLOWED_HOSTS بدلاً منه.
ALLOW_PRIVATE=1 للاختبار المحلي فقط. لا تضبطه على خادم عام.
